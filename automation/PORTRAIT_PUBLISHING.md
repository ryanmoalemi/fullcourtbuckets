# Simple player portrait process

## Owner-facing workflow

1. Generate one full-resolution transparent illustration.
2. The owner approves that image.
3. Upload the whole approved file to `images/players/<exact-player-slug>/portrait.png`.

Use the actual page slug, for example `images/players/breanna-stewart/portrait.png` or `images/players/aja-wilson/portrait.png`. Original PNG is the default. `portrait.webp` or `portrait.avif` is also supported, but keep exactly one portrait file in each player folder. Do not rename a PNG to WebP without conversion. These are publishing folders, not draft storage: files are placed here only AFTER approval.

## Automatic handling

The existing GitHub workflow already responds to `images/players/**` changes. `apply_portraits.py` now calls `portrait_folders.sync` automatically. The folder is matched to the real player JSON and permanent provider ID. Actual dimensions, format, transparency and checksum are read from the original file. The implementation manifest is generated automatically, not edited manually per upload.

No image is resized, recompressed, stretched or regenerated by this path. New images normally retain the full original dimensions, at least 1024 pixels on each side. Existing approved production exports can move into a folder byte-for-byte with their recorded full-resolution provenance. Thumbnails, corrupt files, duplicate files assigned to different players and ambiguous two-image folders are rejected before publication.

The approved compact desktop/mobile layout remains in use. CSS object-fit:cover keeps proportions and crops to the same head-and-shoulders presentation. The source file stays intact. Names and stats are HTML. The stats strip stays below the compact hero. The purple gradient, circles and faint outlined number remain, without the square card or visible caption.

A changed file produces a changed hash-based image URL automatically, avoiding reuse of the previous cached picture. Removing a folder-managed portrait removes its mapping rather than restoring an old thumbnail. Existing non-folder portraits continue to work while the archive is migrated.

## Verification, not extra owner steps

The existing pre-deployment and public-page browser checks remain automatic. The public file checksum must equal the approved/uploaded file; image.decode(), natural dimensions, correct player ID/name/path and desktop/mobile layout must pass. Inspect the actual screenshots before telling the owner a replacement is live. A commit alone is not completed publication. A valid placeholder is not a portrait.

## Scope and outstanding transfer limitation

This implements automatic folder-to-page handling. It does not by itself create a whole-file upload capability in a chat connector. Do not claim an approved local image is uploaded unless the complete file actually reached GitHub and the live checks passed. Do not go back to copying binary images in dozens of chunks, create a new transfer workflow for each player, reduce quality to shorten a tool argument, expose credentials or silently buy services. Use a supported whole-file uploader or the repository's native upload interface.

The owner's one-image-at-a-time approval remains required. The older unattended generation task stays paused. The separate daily/weekly statistics updater is unchanged.
